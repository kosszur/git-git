gitmodules(5)
=============

NAME
----
gitmodules - Submodule-tulajdonságok definiálása

SYNOPSIS
--------
$GIT_WORK_TREE/.gitmodules


DESCRIPTION
-----------

A `.gitmodules` fájl, amely egy Git working tree legfelső szintű
könyvtárában található, egy szövegfájl, amelynek szintaxisa megfelel a
linkgit:git-config[1] követelményeinek.

A fájl submodule-onként egy alszakaszt tartalmaz, és az alszakasz értéke a
submodule neve. A név arra az útvonalra van beállítva, ahová a submodule
hozzáadásra került, hacsak nem lett testre szabva a 'git submodule add'
`--name` opciójával. Minden submodule-szakasz tartalmazza a következő
kötelező kulcsokat is:

submodule.<name>.path::
	Megadja az útvonalat – a Git working tree legfelső szintű
	könyvtárához képest –, ahová a submodule várhatóan checkoutolásra
	kerül. Az útvonalnév nem végződhet `/`-re. Minden submodule-útvonalnak
	egyedinek kell lennie a `.gitmodules` fájlon belül.

submodule.<name>.url::
	Megad egy URL-t, amelyről a submodule repository klónozható.
	Ez lehet egy abszolút URL, amely készen áll a linkgit:git-clone[1]-nek
	való átadásra, vagy (ha `./`-tel vagy `../`-tal kezdődik) egy, a
	szuperprojekt origin repository-jához képest relatív hely.

Ezenkívül számos opcionális kulcs van:

submodule.<name>.update::
	Megadja a megnevezett submodule alapértelmezett frissítési
	eljárását, azaz hogy a szuperprojektben a `git submodule update`
	parancs hogyan frissíti a submodule-t. Ezt csak a `git
	submodule init` használja az azonos nevű konfigurációs változó
	inicializálására. A megengedett értékek itt: 'checkout', 'rebase',
	'merge' vagy 'none', de nem '!command' (biztonsági okokból).
	További részletekért l. az 'update' parancs leírását a
	linkgit:git-submodule[1]-ben.

submodule.<name>.branch::
	Egy remote branch neve az upstream submodule-ban lévő frissítések
	követéséhez. Ha az opció nincs megadva, az alapértelmezés a remote
	`HEAD`. A `.` speciális érték annak jelzésére szolgál, hogy a
	submodule-ban lévő branch neve ugyanaz legyen, mint az aktuális
	repository aktuális branchének neve.  A részletekért l. a `--remote`
	dokumentációját a linkgit:git-submodule[1]-ben.

submodule.<name>.fetchRecurseSubmodules::
	Ezzel az opcióval szabályozható ennek a submodule-nak a rekurzív
	fetchelése. Ha ez az opció a szuperprojekt `.git/config`-jában lévő
	submodule-bejegyzésben is jelen van, az ottani beállítás felülírja a
	`.gitmodules`-ban találhatót.
	Mindkét beállítás felülbírálható a parancssorban a `git fetch` és a
	`git pull` `--[no-]recurse-submodules` opciójával.

submodule.<name>.ignore::
	Megadja, hogy milyen körülmények között jelzi a `git status` és a
	diff-család a submodule-t módosítottként. A következő értékek
	támogatottak:
+
--
	all;; A submodule soha nem számít módosítottnak (de ennek ellenére
	    megjelenik a status és a commit kimenetében, ha stage-elve lett).
	    A `(new commits)` melletti submodule hozzáadása felülbírálható a
	    `git add --force <submodule.path>` használatával.
	    Ez a beállítás a `status`, `update-index`, `diff` és `log`
	    parancsokat érinti (a mögöttes `diff` miatt).

	dirty;; A submodule working tree-jének minden módosítása figyelmen
	    kívül marad, csak a submodule `HEAD`-je és a szuperprojektben
	    rögzített állapota közötti commitolt eltérések számítanak.

	untracked;; Csak a submodule-okban lévő nem követett fájlok maradnak
	    figyelmen kívül. A commitolt eltérések és a követett fájlok
	    módosításai megjelennek.

	none;; A submodule-ok egyetlen módosítása sem marad figyelmen kívül,
	    minden commitolt eltérés, valamint a követett és nem követett
	    fájlok módosításai megjelennek. Ez az alapértelmezett opció.

Ha ez az opció a szuperprojekt `.git/config`-jában lévő
submodule-bejegyzésben is jelen van, az ottani beállítás felülírja a
`.gitmodules`-ban találhatót.

Mindkét beállítás felülbírálható a parancssorban az `--ignore-submodules`
opcióval. A `git submodule` parancsokat ez a beállítás nem érinti.
--

submodule.<name>.shallow::
	Ha true-ra van állítva, ennek a submodule-nak a klónozása shallow
	klónként történik (1-es előzmény-mélységgel), hacsak a felhasználó
	explicit módon nem kér nem-shallow klónt.

NOTES
-----

A Git nem engedi meg, hogy a working tree-ben lévő `.gitmodules` fájl
szimbolikus link legyen, és megtagadja egy ilyen tree-bejegyzés
checkoutolását. Ez konzisztensen tartja a viselkedést, amikor a fájlt az
indexből vagy egy tree-ből érik el, szemben a fájlrendszerből való
eléréssel, és segít a Gitnek megbízhatóan érvényesíteni a fájltartalom
biztonsági ellenőrzéseit.

EXAMPLES
--------

Tekintsük a következő `.gitmodules` fájlt:

----
[submodule "libfoo"]
	path = include/foo
	url = git://foo.com/git/lib.git

[submodule "libbar"]
	path = include/bar
	url = git://bar.com/git/lib.git
----

Ez két submodule-t definiál, a `libfoo`-t és a `libbar`-t. Ezek várhatóan
az `include/foo` és az `include/bar` útvonalakra kerülnek checkoutolásra,
és mindkét submodule-hoz meg van adva egy URL, amely a submodule-ok
klónozására használható.
