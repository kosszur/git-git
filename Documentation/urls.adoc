GIT URLS[[URLS]]
----------------

Az URL-ek általában tartalmazzák az átviteli protokollra, a remote
szerver címére és a repository elérési útjára vonatkozó információkat.
Az átviteli protokolltól függően ezen információk egy része hiányozhat.

A Git támogatja az ssh, git, http és https protokollokat (ezenkívül az
ftp és az ftps használható fetchelésre, de ez nem hatékony és elavult;
ne használd őket).

A natív átvitel (azaz a `git://` URL) nem végez hitelesítést, és
óvatosan kell használni nem biztonságos hálózatokon.

A következő szintaxisok használhatók velük:

- `ssh://[<user>@]<host>[:<port>]/<path-to-git-repo>`
- `git://<host>[:<port>]/<path-to-git-repo>`
- `http[s]://<host>[:<port>]/<path-to-git-repo>`
- `ftp[s]://<host>[:<port>]/<path-to-git-repo>`

Az ssh protokollal egy alternatív, scp-szerű szintaxis is használható:

- `[<user>@]<host>:/<path-to-git-repo>`

Ezt a szintaxist csak akkor ismeri fel, ha nincs perjel az első
kettőspont előtt. Ez segít megkülönböztetni egy kettőspontot tartalmazó
helyi útvonalat. Például a `foo:bar` helyi útvonal megadható abszolút
útvonalként, vagy `./foo:bar` alakban, hogy ne értelmezze tévesen ssh
url-ként.

Az ssh és a git protokoll ezenkívül támogatja a `~<username>`
kibontását:

- `ssh://[<user>@]<host>[:<port>]/~<user>/<path-to-git-repo>`
- `git://<host>[:<port>]/~<user>/<path-to-git-repo>`
- `[<user>@]<host>:~<user>/<path-to-git-repo>`

Helyi repository-khoz, amelyeket a Git szintén natívan támogat, a
következő szintaxisok használhatók:

- `/path/to/repo.git/`
- `file:///path/to/repo.git/`

előbbi maga után vonja a `--local` opciót. A részletekért lásd a
linkgit:git-clone[1]-et.
endif::git-clone[]

Ez a két szintaxis többnyire egyenértékű, kivéve, hogy az előbbi maga
után vonja a `--local` opciót.
endif::git-clone[]

A `git clone`, a `git fetch` és a `git pull` — de a `git push` nem —
egy megfelelő bundle fájlt is elfogad. Lásd linkgit:git-bundle[1].

Amikor a Git nem tudja, hogyan kezeljen egy adott átviteli protokollt,
megpróbálja a `remote-<transport>` remote helpert használni, ha van
ilyen. Egy remote helper kifejezett kéréséhez a következő szintaxis
használható:

- `<transport>::<address>`

ahol az _<address>_ lehet egy útvonal, egy szerver és útvonal, vagy egy
tetszőleges URL-szerű karakterlánc, amelyet a meghívott konkrét remote
helper felismer. A részletekért lásd a linkgit:gitremote-helpers[7]-et.

Ha sok hasonló nevű remote repository van, és más formátumot szeretnél
használni hozzájuk (úgy, hogy az általad használt URL-ek működő
URL-ekre íródjanak át), létrehozhatsz egy ilyen alakú konfigurációs
szakaszt:

[verse]
--
	[url "__<actual-url-base>__"]
		insteadOf = _<other-url-base>_
--

Például ezzel:

------------
	[url "git://git.host.xz/"]
		insteadOf = host.xz:/path/to/
		insteadOf = work:
------------

egy olyan URL, mint a "work:repo.git" vagy a
"host.xz:/path/to/repo.git", minden URL-t elfogadó kontextusban
"git://git.host.xz/repo.git" alakra íródik át.

Ha csak a pushhoz szeretnél URL-eket átírni, létrehozhatsz egy ilyen
alakú konfigurációs szakaszt:

[verse]
--
	[url "__<actual-url-base>__"]
		pushInsteadOf = _<other-url-base>_
--

Például ezzel:

------------
	[url "ssh://example.org/"]
		pushInsteadOf = git://example.org/
------------

egy olyan URL, mint a "git://example.org/path/to/repo.git",
pusholáskor "ssh://example.org/path/to/repo.git" alakra íródik át, de a
pullok továbbra is az eredeti URL-t használják.
