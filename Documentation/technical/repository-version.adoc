[[_git_repository_format_versions]]
== A Git repository-formátum verziói

Minden git repository egy numerikus verzióval van megjelölve a `config`
fájljának `core.repositoryformatversion` kulcsában. Ez a verzió határozza
meg a lemezen tárolt repository-adatokon való műveletvégzés szabályait. A
git egy olyan implementációjának, amely nem ért egy adott, a lemezen
tárolt repository által hirdetett verziót, NEM SZABAD műveletet végeznie
azon a repository-n; ha mégis megteszi, azzal nemcsak hibás eredmények
előállítását, hanem tényleges adatvesztést is kockáztat.

E szabály miatt a verzióemeléseket a lehető legkevesebbre kell
korlátozni. Ehelyett általában ezeket a stratégiákat részesítjük
előnyben:

  - az egyes adatfájlok (pl. index, packfile-ok stb.)
    formátumverzió-számának emelése. Ez az inkompatibilitásokat csak
    ezekre a fájlokra korlátozza.

  - olyan új adatok bevezetése, amelyek elegánsan lefokozódnak, ha
    régebbi kliensek használják őket (pl. a pack bitmap fájlokat a
    régebbi kliensek figyelmen kívül hagyják, egyszerűen nem használják
    ki az általuk nyújtott optimalizációt).

A repository egészére vonatkozó formátumverzió-emelésnek csak olyan
változtatás részének szabad lennie, amelyet nem lehet önállóan verziózni.
Ha például valaki megváltoztatná az objektumok elérhetőségi szabályait
vagy a refek zárolásának szabályait, az a repository-formátumverzió
emelését igényelné.

Vedd figyelembe, hogy ez csak a repository lemezes tartalmának közvetlen
elérésére vonatkozik. Egy régebbi kliens, amely csak a `0` formátumot
érti, továbbra is csatlakozhat `git://` protokollon keresztül egy `1`
formátumot használó repository-hoz, amíg a szerverfolyamat érti az `1`
formátumot.

Egy verzióemelés (akár az egész repository-ra, akár egyetlen fájlra
vonatkozóan) bevezetésének előnyben részesített stratégiája az, hogy
megtanítjuk a gitet az új formátum olvasására, és config-kapcsolóval vagy
parancssori opcióval engedélyezzük az új formátum írását (kísérletezés
céljából, vagy azoknak, akiket nem érdekel a régebbi gitekkel való
visszafelé kompatibilitás). Ezután egy hosszú időszak után, amíg az
olvasási képesség elterjed, alapértelmezés szerint áttérhetünk az új
formátum írására.

A jelenleg definiált formátumverziók a következők:

[[_version_0]]
=== `0`. verzió

Ez az a formátum, amelyet a git kezdeti verziója definiált, beleértve, de
nem kizárólag a repository-könyvtár formátumát, a repository konfigurációs
fájlját, valamint az objektum- és reftárolást. A git teljes viselkedésének
leírása túlmutat e dokumentum keretein.

[[_version_1]]
=== `1`. verzió

Ez a formátum azonos a `0` verzióval, a következő kivételekkel:

  1. A `core.repositoryformatversion` változó olvasásakor egy olyan git
     implementációnak, amely támogatja az 1-es verziót, KÖTELEZŐ
     beolvasnia a konfigurációs fájl `extensions` szakaszában található
     bármely konfigurációs kulcsot is.

  2. Ha egy 1-es verziójú repository olyan `extensions.*` kulcsokat ad
     meg, amelyeket a futó git nem implementált, a műveletnek NEM SZABAD
     folytatódnia. Hasonlóképpen, ha bármely ismert kulcs értékét nem
     érti az implementáció, a műveletnek NEM SZABAD folytatódnia.

Vedd figyelembe, hogy ha nincs kiterjesztés megadva a config fájlban,
akkor a `core.repositoryformatversion` értékét `0`-ra AJÁNLOTT állítani
(az `1`-re állítása semmilyen előnnyel nem jár, és inkompatibilissá teszi
a repository-t a git régebbi implementációival).

A definiált kiterjesztéseket a linkgit:git-config[1] `extensions.*`
szakasza sorolja fel. Bármely implementációnak, amely új kiterjesztést
kíván definiálni, fel kell jegyeznie azt ott, hogy lefoglalja a nevet.
