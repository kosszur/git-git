[[_scalar]]
Scalar
======

A Scalar egy repository-kezelő eszköz, amely a Gitet nagy repository-kban
való használatra optimalizálja. Ezt úgy éri el, hogy segít a
felhasználóknak kihasználni a Git fejlett teljesítmény-funkcióit. A
legtöbb más beépített Git-paranccsal ellentétben a Scalar nem a 'git'
alparancsaként fut; ehelyett külön végrehajtható állományként épül fel,
amely a saját alparancsainak sorozatát tartalmazza.

[[_background]]
Háttér
------

A Scalart eredetileg a Git kiegészítőjének tervezték, és .NET Core
alkalmazásként valósították meg. A VFS for Git projekt (egy másik, a nagy
repository-kkal való munka élményét javító alkalmazás) tanulságai alapján
készült. Kezdeti megvalósítása során a Scalar a Git Microsoft-forkjának
egyedi funkcióira támaszkodott, amelyek azóta bekerültek a core Gitbe:

* partial clone,
* commit-gráfok,
* multi-pack index,
* sparse checkout (cone mód),
* ütemezett háttérkarbantartás,
* stb.

Miután a szükséges Git-funkciók a helyükre kerültek, és megfogalmazódott
az igény, hogy a Scalar előnyeit a tágabb Git-közösség is élvezhesse,
magát a Scalar alkalmazást C#-ról C-re portolták, és integrálták az
upstreambe.

[[_features]]
Funkciók
--------

A Scalar két fő funkcionális részből áll: automatikusan konfigurálja a
beépített Git teljesítmény-funkciókat, és kezeli a repository-k
enlistmentjeit.

A Scalar által konfigurált Git teljesítmény-funkciók (példákért lásd a
„Háttér" részt) jelentős teljesítménybeli előnyt biztosítanak a nagy
repository-knak, de vagy túl kísérletiek ahhoz, hogy a Git egészében
engedélyezzük őket, vagy csak a nagy repository-knak hasznosak. Ahogy új
funkciók jelennek meg, a Scalart is frissíteni kell, hogy beépítse őket.
Ez megakadályozza, hogy az eszköz elavuljon, egyben utat is biztosít
ahhoz, hogy a funkciók könnyebben eljussanak a megfelelő felhasználókhoz.

Az enlistmentek révén tudja a Scalar, hogy a felhasználó rendszerén mely
repository-knak kell használniuk a Scalar által konfigurált funkciókat.
Ez lehetővé teszi a teljesítménybeállítások frissítését, amikor újakat
adnak az eszközhöz, valamint a repository-karbantartás központi kezelését.
Az enlistment-struktúra – egy gyökérkönyvtár egy `src/` alkönyvtárral,
amely magát a klónozott repository-t tartalmazza – arra ösztönzi a
felhasználókat, hogy a buildkimeneteket a repository-n kívülre irányítsák,
elkerülve azt a teljesítménykorlátozó többletköltséget, amit ezeknek a
fájloknak a Gitben való figyelmen kívül hagyása jelentene.

[[_design]]
Felépítés
---------

A Scalar C-ben van megvalósítva, és a Gittel részben a Git gyermek-
folyamatként való meghívásával, részben a `libgit.a` közvetlen
használatával lép kapcsolatba. Belül nagyjából úgy épül fel, mint az
alparancsokkal rendelkező más beépített parancsok (pl. `git stash`):
minden alparancshoz tartozik egy `cmd_<subcommand>()` függvény, amelyeket
egy `cmd_main()` függvény irányít. A legtöbb opció alparancsonként egyedi,
a `scalar` pedig tiszteletben tart néhány „globális" `git` opciót (pl. a
`-c` és a `-C` opciót).

Mivel a `scalar` nem Git-alparancsként hívódik meg (mint a `git scalar`),
saját végrehajtható állományként épül fel és települ a `bin/` könyvtárba,
a `git`, a `git-gui` stb. mellé.
