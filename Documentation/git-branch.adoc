git-branch(1)
=============

NAME
----
git-branch - Branchek listázása, létrehozása vagy törlése

SYNOPSIS
--------
[synopsis]
git branch [--color[=<when>] | --no-color] [--show-current]
	   [-v [--abbrev=<n> | --no-abbrev]]
	   [--column[=<options>] | --no-column] [--sort=<key>]
	   [--merged [<commit>]] [--no-merged [<commit>]]
	   [--contains [<commit>]] [--no-contains [<commit>]]
	   [(--forked <branch>)...]
	   [--points-at <object>] [--format=<format>]
	   [(-r|--remotes) | (-a|--all)]
	   [--list] [<pattern>...]
git branch [--track[=(direct|inherit)] | --no-track] [-f]
	   [--recurse-submodules] <branch-name> [<start-point>]
git branch (--set-upstream-to=<upstream>|-u <upstream>) [<branch-name>]
git branch --unset-upstream [<branch-name>]
git branch (-m|-M) [<old-branch>] <new-branch>
git branch (-c|-C) [<old-branch>] <new-branch>
git branch (-d|-D) [-r] <branch-name>...
git branch --edit-description [<branch-name>]
git branch [--dry-run] (--delete-merged <pattern>)... [<branch-pattern>...]

DESCRIPTION
-----------

Ha a `--list` meg van adva, vagy ha nincsenek nem-opció argumentumok, a
meglévő branchek kerülnek listázásra; az aktuális branch zöld színnel lesz
kiemelve és csillaggal jelölve. A linkelt worktree-kben checkoutolt
branchek ciánkék színnel és pluszjellel lesznek kiemelve. A `-r` opció
hatására a remote-tracking branchek kerülnek listázásra,
az `-a` opció pedig mind a helyi, mind a remote brancheket megjeleníti.

Ha meg van adva egy `<pattern>`,
az shell helyettesítő karakterként szolgál a kimenet illeszkedő
branchekre való szűkítéséhez. Ha több minta van megadva, egy branch
akkor jelenik meg, ha bármelyik mintára illeszkedik.

Vedd figyelembe, hogy ha
`<pattern>`-t adsz meg, a `--list`-et is használnod kell; különben a
parancs branch-létrehozásként lehet értelmezve.

A `--contains` csak azokat a brancheket mutatja, amelyek tartalmazzák a
megadott commitot (más szóval azokat a brancheket, amelyek csúcs-commitjai
a megadott commit leszármazottai), a `--no-contains` ennek a fordítottját.
A `--merged` esetén csak azok a branchek kerülnek listázásra, amelyek be
vannak merge-elve a megadott commitba (azaz azok a branchek, amelyek
csúcs-commitjai elérhetők a megadott commitból). A `--no-merged` esetén
csak azok a branchek kerülnek listázásra, amelyek nincsenek merge-elve a
megadott commitba. Ha az _<commit>_ argumentum hiányzik, alapértelmezésben
a `HEAD`-et veszi (azaz az aktuális branch csúcsát). A `--forked` esetén
csak azok a branchek kerülnek listázásra, amelyek konfigurált upstreamje
illeszkedik a megadott branchre vagy mintára.

A parancs második formája egy új, _<branch-name>_ nevű branchfejet hoz
létre, amely az aktuális `HEAD`-re mutat, vagy a megadott
_<start-point>_-ra, ha ilyen szerepel. Speciális esetként, a
_<start-point>_ helyén használhatod a `<rev-A>...<rev-B>` alakot az
_<rev-A>_ és _<rev-B>_ merge-alapjának rövidítéseként, ha pontosan egy
merge-alap létezik. Az _<rev-A>_ és _<rev-B>_ közül legfeljebb az egyiket
hagyhatod el, ekkor az alapértelmezés `HEAD` lesz.

Vedd figyelembe, hogy ez létrehozza az új branchet, de nem vált át rá a
munkakönyvtárban; az új branchre való átváltáshoz használd a
`git switch <new-branch>` parancsot.

Amikor egy helyi branch egy remote-tracking branchből indul, a Git
beállítja a branchet (konkrétan a `branch.<name>.remote` és a
`branch.<name>.merge` konfigurációs bejegyzéseket), hogy a `git pull` a
megfelelő módon merge-eljen a remote-tracking branchből. Ez a viselkedés
a globális `branch.autoSetupMerge` konfigurációs kapcsolóval
megváltoztatható. Ez a beállítás felülírható a `--track` és `--no-track`
opciókkal, és később módosítható a `git branch --set-upstream-to`
használatával.

A `-m` vagy `-M` opcióval az _<old-branch>_ át lesz nevezve
_<new-branch>_-re. Ha az _<old-branch>_-nak volt hozzá tartozó reflogja,
az is át lesz nevezve _<new-branch>_-re, és egy reflog-bejegyzés jön létre
a branch átnevezésének megörökítésére. Ha az _<new-branch>_ már létezik,
a `-M`-et kell használni az átnevezés kikényszerítéséhez.

A `-c` és `-C` opciók pontosan ugyanazzal a szemantikával rendelkeznek,
mint a `-m` és a `-M`, azzal a különbséggel, hogy a branch átnevezése
helyett az egy új néven lesz lemásolva, a konfigurációjával és a
reflogjával együtt.

A `-d` vagy `-D` opcióval az _<branch-name>_ törölve lesz. Egyszerre
több branch is megadható törlésre. Ha a branchnek jelenleg van reflogja,
az is törölve lesz.

Használd a `-r`-t a `-d`-vel együtt a remote-tracking branchek
törléséhez. Vedd figyelembe, hogy remote-tracking brancheket csak akkor
érdemes törölni, ha azok már nem léteznek a remote repository-ban, vagy
ha a `git fetch` úgy van konfigurálva, hogy ne töltse le őket újra. Lásd
még a linkgit:git-remote[1] `prune` alparancsát az összes elavult
remote-tracking branch eltávolításához.


OPTIONS
-------
`-d`::
`--delete`::
	Törli a brancht. A branchnek teljesen be kell legyen merge-elve
	az upstream branchjébe, vagy a `HEAD`-be, ha nem volt beállítva
	upstream a `--track` vagy a `--set-upstream-to` segítségével.

`-D`::
	Rövidítés a `--delete --force`-hoz.

`--create-reflog`::
	Létrehozza a branch reflogját. Ez bekapcsolja a branch ref
	összes változásának naplózását, lehetővé téve a dátum alapú
	sha1-kifejezések, például `<branch-name>@{yesterday}` használatát.
	Vedd figyelembe, hogy nem bare repository-kban a reflogok
	általában alapértelmezetten be vannak kapcsolva a
	`core.logAllRefUpdates` konfigurációs opció révén.
	A negált `--no-create-reflog` alak csak egy korábbi
	`--create-reflog`-ot ír felül, de jelenleg nem negálja a
	`core.logAllRefUpdates` beállítását.

`-f`::
`--force`::
	Visszaállítja az _<branch-name>_-t az _<start-point>_-ra, még
	akkor is, ha az _<branch-name>_ már létezik. A `-f` nélkül a
	`git branch` megtagadja egy meglévő branch megváltoztatását.
	A `-d`-vel (vagy `--delete`-tel) kombinálva engedélyezi a branch
	törlését a merge-állapotától függetlenül, vagy attól függetlenül,
	hogy egyáltalán érvényes commitra mutat-e. A `-m`-mel (vagy
	`--move`-val) kombinálva engedélyezi a branch átnevezését még
	akkor is, ha az új branchnév már létezik; ugyanez vonatkozik a
	`-c`-re (vagy a `--copy`-ra) is.
+
Vedd figyelembe, hogy a `git branch -f <branch-name> [<start-point>]`,
még `-f`-fel is, megtagadja egy olyan meglévő _<branch-name>_ branch
megváltoztatását, amely egy ugyanahhoz a repository-hoz linkelt másik
worktree-ben van checkoutolva.

`-m`::
`--move`::
	Áthelyezi/átnevezi a brancht, a konfigurációjával és a
	reflogjával együtt.

`-M`::
	Rövidítés a `--move --force`-hoz.

`-c`::
`--copy`::
	Lemásolja a brancht, a konfigurációjával és a reflogjával
	együtt.

`-C`::
	Rövidítés a `--copy --force`-hoz.

`--color[=<when>]`::
	Színezi a brancheket az aktuális, a helyi és a remote-tracking
	branchek kiemeléséhez.
	Az érték `always` (az alapértelmezett), `never` vagy `auto` lehet.

`--no-color`::
	Kikapcsolja a branchszínezést, még akkor is, ha a konfigurációs
	fájl alapértelmezésben a kimenet színezését adja meg.
	Ugyanaz, mint a `--color=never`.

`-i`::
`--ignore-case`::
	A branchek rendezése és szűrése kis- és nagybetűre nem
	érzékeny.

`--omit-empty`::
	Nem ír ki új sort a formázott refek után, ahol a formátum üres
	stringgé bővül.

`--column[=<options>]`::
`--no-column`::
	A branchlistát oszlopokban jeleníti meg. Az opciók szintaxisáért
	lásd a `column.branch` konfigurációs változót. Az opciók nélküli
	`--column` és `--no-column` az `always`, illetve a `never`
	értékkel egyenértékű.
+
Ez az opció csak nem-verbose módban alkalmazható.

`--sort=<key>`::
	Rendez az _<key>_ alapján. Előtag `-` a csökkenő sorrendű
	rendezéshez. A `--sort=<key>` opció többször is használható,
	ekkor az utolsó kulcs lesz az elsődleges. A támogatott kulcsok
	ugyanazok, mint a linkgit:git-for-each-ref[1]-ben. A rendezési
	sorrend alapértelmezésben a `branch.sort` változóban
	konfigurált értéket veszi, ha az létezik, egyébként a teljes
	refnév (a `refs/...` előtaggal együtt) szerinti rendezést.
	Ez elsőként a leválasztott `HEAD`-et listázza (ha van), majd
	a helyi brancheket, végül a remote-tracking brancheket. Lásd
	linkgit:git-config[1].

`-r`::
`--remotes`::
	Listázza vagy törli (ha `-d`-vel együtt van használva) a
	remote-tracking brancheket. Kombináld a `--list`-tel az
	opcionális minta(minták) illesztéséhez.

`-a`::
`--all`::
	Listázza mind a remote-tracking brancheket, mind a helyi
	brancheket. Kombináld a `--list`-tel az opcionális minta(minták)
	illesztéséhez.

`-l`::
`--list`::
	Listázza a brancheket. Az opcionális `<pattern>...` megadásával,
	pl. `git branch --list 'maint-*'`, csak a mintá(k)ra illeszkedő
	brancheket listázza.

`--show-current`::
	Kiírja az aktuális branch nevét. Leválasztott `HEAD` állapotban
	semmi nem kerül kiírásra.

`--delete-merged <pattern>`::
	Törli azokat a helyi brancheket, amelyek konfigurált upstreamje
	illeszkedik az _<pattern>_-re, de csak akkor, ha a csúcsuk
	elérhető abból az upstreamből. Más szóval, a branchen végzett
	munka már megérkezett az upstreambe, amelyet követ, így a helyi
	másolatra már nincs szükség. Az _<pattern>_ megnevezhet egy
	refet, egy remote-ot (a `HEAD`-je által mutatott branch
	használatával), vagy egy shell-stílusú globot. Az opció
	megismételhető az upstream-illesztés szélesítéséhez.
	Az opcionális _<branch-pattern>_ argumentumok korlátozzák, mely
	helyi branchek jönnek szóba, pl. `git branch --delete-merged
	'origin/*' 'topic-*'`.
+
Egy branch nem kerül törlésre, ha:
+
--
* a konfigurált upstream refje már nem létezik,
* bármely worktree-ben checkoutolva van,
* a `branch.<name>.remote` által konfigurált remote-ra pusholása
  frissítené az upstreamjét, így nem különböztethető meg egy olyan
  branchtől, amely csak egy pull után látszik teljesen
  merge-eltnek; ezt a remote konfigurált push- és fetch-refspecjei
  határozzák meg,
* egy nem törlésre kerülő branch helyi upstreamje, vagy
* a `branch.<name>.deleteMerged` `false`-ra van állítva.
--
+
Ha egy ilyen helyi upstream branch saját upstreamjét ugyanez a
művelet törli, az upstream-konfigurációja törlődik.
+
Az a branch, amelynek munkája még nincs merge-elve az upstreambe,
csendben kimarad. Töröld a `git branch -D` paranccsal, ha mindenképp
el akarod távolítani.

`--dry-run`::
	A `--delete-merged`-del együtt kiírja, mely branchek kerülnének
	törlésre, és bármely ref érintése nélkül kilép. Hasznos egy
	széles minta, például `'origin/*'` ellenőrzésére a törlés
	végrehajtása előtt.

`-v`::
`-vv`::
`--verbose`::
	Lista módban
	kiírja az sha1-et és a commit tárgysorát minden fejhez, az
	upstream branchhez való viszonnyal együtt (ha van ilyen). Ha
	kétszer van megadva, a linkelt worktree útvonalát (ha van) és az
	upstream branch nevét is kiírja (lásd még: `git remote show
	<remote>`). Vedd figyelembe, hogy az aktuális worktree
	`HEAD`-jéhez nem kerül kiírásra útvonal (az mindig az aktuális
	könyvtárad lesz).

`-q`::
`--quiet`::
	Csendesebb legyen a branch létrehozásakor vagy törlésekor, elnyomva
	a nem hibaüzeneteket.

`--abbrev=<n>`::
	A commit objektumnevet megjelenítő verbose listázásban a
	legrövidebb, legalább _<n>_ hexajegy hosszú előtagot mutatja,
	amely egyértelműen hivatkozik az objektumra.
	Az alapértelmezett érték 7, és felülírható a `core.abbrev`
	konfigurációs opcióval.

`--no-abbrev`::
	A teljes sha1-eket jeleníti meg a kimeneti listában, rövidítés
	nélkül.

`-t`::
`--track[=(direct|inherit)]`::
	Új branch létrehozásakor beállítja a `branch.<name>.remote` és a
	`branch.<name>.merge` konfigurációs bejegyzéseket, hogy
	"upstream" tracking-konfigurációt állítson be az új branchhez.
	Ez a konfiguráció mondja meg a gitnek, hogy mutassa a két branch
	közötti kapcsolatot a `git status`-ban és a `git branch -v`-ben.
	Emellett irányítja, hogy az argumentum nélküli `git pull` az
	upstreamből húzzon, amikor az új branch ki van checkoutolva.
+
A pontos upstream branch az opcionális argumentumtól függően kerül
kiválasztásra: a `-t`, `--track` vagy `--track=direct` azt jelenti,
hogy magát a start-point branchet kell upstreamként használni; a
`--track=inherit` azt jelenti, hogy a start-point branch upstream-
konfigurációját kell másolni.
+
A `branch.autoSetupMerge` konfigurációs változó adja meg, hogyan
viselkedjen a `git switch`, a `git checkout` és a `git branch`, ha sem
a `--track`, sem a `--no-track` nincs megadva:
+
Az alapértelmezett `true` opció úgy viselkedik, mintha `--track=direct`
lett volna megadva, amikor a start-point egy remote-tracking branch.
A `false` úgy viselkedik, mintha `--no-track` lett volna megadva. Az
`always` úgy viselkedik, mintha `--track=direct` lett volna megadva.
Az `inherit` úgy viselkedik, mintha `--track=inherit` lett volna
megadva. A `simple` úgy viselkedik, mintha `--track=direct` lett volna
megadva, de csak akkor, ha az _<start-point>_ egy remote-tracking
branch, és az új branch neve megegyezik a remote branch nevével.
+
A `branch.<name>.remote` és a `branch.<name>.merge` opciók
használatáról bővebben lásd a linkgit:git-pull[1] és a
linkgit:git-config[1] leírását.

`--no-track`::
	Nem állítja be az "upstream" konfigurációt, még akkor sem, ha a
	`branch.autoSetupMerge` konfigurációs változó be van állítva.

`--recurse-submodules`::
	EZ AZ OPCIÓ KÍSÉRLETI! Hatására az aktuális parancs
	rekurzívan bejárja a submodule-okat, ha a
	`submodule.propagateBranches` be van kapcsolva. Lásd a
	`submodule.propagateBranches`-t a linkgit:git-config[1]-ben.
	Jelenleg csak a branch-létrehozás támogatott.
+
Branch-létrehozásban használva egy új, _<branch-name>_ nevű branch jön
létre a szuperprojektben és a szuperprojekt _<start-point>_-jában lévő
összes submodule-ban. A submodule-okban a branch a szuperprojekt
_<start-point>_-jában lévő submodule-commitra fog mutatni, de a branch
tracking-információja a submodule saját branchei és remote-jai alapján
kerül beállításra, pl. a `git branch --recurse-submodules topic
origin/main` létrehozza a "topic" nevű submodule-branchet, amely a
szuperprojekt "origin/main"-jében lévő submodule-commitra mutat, de a
submodule saját "origin/main"-jét követi.

`--set-upstream`::
	Mivel ennek az opciónak zavaros volt a szintaxisa, már nem
	támogatott. Használd inkább a `--track`-et vagy a
	`--set-upstream-to`-t.

`-u <upstream>`::
`--set-upstream-to=<upstream>`::
	Beállítja az _<branch-name>_ tracking-információját, hogy az
	_<upstream>_ legyen az _<branch-name>_ upstream branchjeként
	kezelve. Ha nincs megadva _<branch-name>_, akkor az
	alapértelmezés az aktuális branch.

`--unset-upstream`::
	Eltávolítja az _<branch-name>_ upstream-információját. Ha nincs
	megadva branch, az alapértelmezés az aktuális branch.

`--edit-description`::
	Megnyit egy szerkesztőt, hogy szerkeszthesd a szöveget, amely
	elmagyarázza, mire való a branch; ezt más parancsok (pl. a
	`format-patch`, a `request-pull` és a `merge` (ha engedélyezve
	van)) használják fel. Többsoros magyarázatok is használhatók.

`--contains [<commit>]`::
	Csak azokat a brancheket listázza, amelyek tartalmazzák az
	_<commit>_-ot (`HEAD`, ha nincs megadva). Magával vonja a
	`--list`-et.

`--no-contains [<commit>]`::
	Csak azokat a brancheket listázza, amelyek nem tartalmazzák az
	_<commit>_-ot (`HEAD`, ha nincs megadva). Magával vonja a
	`--list`-et.

`--merged [<commit>]`::
	Csak azokat a brancheket listázza, amelyek csúcsai elérhetők az
	_<commit>_-ból (`HEAD`, ha nincs megadva). Magával vonja a
	`--list`-et.

`--no-merged [<commit>]`::
	Csak azokat a brancheket listázza, amelyek csúcsai nem érhetők
	el az _<commit>_-ból (`HEAD`, ha nincs megadva). Magával vonja a
	`--list`-et.

`--forked <branch>`::
	Csak azokat a brancheket listázza, amelyek konfigurált
	upstreamje illeszkedik az _<branch>_-re. Az argumentum lehet
	egy ref (pl. `origin/main`, `master`), egy remote neve, mint az
	`origin`, azon branch esetében, amelyre az `origin/HEAD` mutat,
	vagy egy shell-stílusú glob (pl. `'origin/*'`). Az opció
	megismételhető a szűrő szélesítéséhez. Magával vonja a
	`--list`-et.

`--points-at <object>`::
	Csak az _<object>_ brancheit listázza.

`--format <format>`::
	Egy string, amely a megjelenített branch ref és az általa
	mutatott objektum `%(fieldname)` mezőit interpolálja. Az
	_<format>_ ugyanaz, mint a linkgit:git-for-each-ref[1]-ben.

_<branch-name>_::
	A létrehozandó vagy törlendő branch neve.
	Az új branchnévnek meg kell felelnie a
	linkgit:git-check-ref-format[1] által meghatározott összes
	ellenőrzésnek. Ezek közül néhány korlátozhatja a branchnévben
	megengedett karaktereket.

_<start-point>_::
	Az új branchfej erre a commitra fog mutatni. Megadható
	branchnévként, commit-id-ként vagy tagként. Ha ez az opció
	el van hagyva, az aktuális `HEAD` kerül felhasználásra helyette.

_<old-branch>_::
	Egy meglévő branch neve. Ha ez az opció el van hagyva, az
	aktuális branch neve kerül felhasználásra helyette.

_<new-branch>_::
	Az új név egy meglévő branchhez. Ugyanazok a korlátozások
	érvényesek, mint az _<branch-name>_-re.

CONFIGURATION
-------------
A `pager.branch` csak branchek listázásakor van figyelembe véve, azaz
amikor a `--list` használatban van vagy magától értetődik. Az
alapértelmezés a pager használata.
Lásd linkgit:git-config[1].

EXAMPLES
--------

Fejlesztés indítása egy ismert tagből::
+
------------
$ git clone git://git.kernel.org/pub/scm/.../linux-2.6 my2.6
$ cd my2.6
$ git branch my2.6.14 v2.6.14   <1>
$ git switch my2.6.14
------------
+
<1> Ez a lépés és a következő egyetlen lépésbe is összevonható a
    "checkout -b my2.6.14 v2.6.14" használatával.

Egy szükségtelen branch törlése::
+
------------
$ git clone git://git.kernel.org/.../git.git my.git
$ cd my.git
$ git branch -d -r origin/todo origin/html origin/man   <1>
$ git branch -D test                                    <2>
------------
+
<1> Törli a "todo", a "html" és a "man" remote-tracking brancheket. A
    következő `git fetch` vagy `git pull` újra létrehozza őket, hacsak
    nem konfigurálod úgy, hogy ne tegye. Lásd linkgit:git-fetch[1].
<2> Törli a "test" brancht még akkor is, ha a "master" branchnek (vagy
    bármelyik éppen checkoutolt branchnek) nincs meg az összes commitja

Egy adott remote branchjeinek listázása::
+
------------
$ git branch -r -l '<remote>/<pattern>'                 <1>
$ git for-each-ref 'refs/remotes/<remote>/<pattern>'    <2>
------------
+
<1> Az `-a` használata összemosná az _<remote>_-ot bármely helyi
    branchcsel, amely véletlenül ugyanazzal az _<remote>_ mintával van
    prefixelve.
<2> A `for-each-ref` sokféle opciót elfogad. Lásd
    linkgit:git-for-each-ref[1]

A mintákat általában idézőjelbe kell tenni.

NOTES
-----

Ha olyan brancht hozol létre, amelyre azonnal át akarsz váltani,
egyszerűbb a `git switch` parancsot használni a `-c` opciójával, hogy
ugyanezt egyetlen paranccsal megtedd.

A `--contains`, a `--no-contains`, a `--merged` és a `--no-merged`
opciók négy egymáshoz kapcsolódó, de eltérő célt szolgálnak:

- A `--contains <commit>` az összes olyan branch megtalálására szolgál,
  amelyre külön figyelmet kell fordítani, ha az _<commit>_ rebase-elésre
  vagy amendelésre kerülne, mivel ezek a branchek tartalmazzák a
  megadott _<commit>_-ot.

- A `--no-contains <commit>` ennek a fordítottja, azaz azok a branchek,
  amelyek nem tartalmazzák a megadott _<commit>_-ot.

- A `--merged` az összes olyan branch megtalálására szolgál, amely
  biztonságosan törölhető, mivel ezek a branchek teljesen benne
  foglaltatnak a `HEAD`-ben.

- A `--no-merged` azoknak a brancheknek a megtalálására szolgál,
  amelyek a `HEAD`-be való merge-elés jelöltjei, mivel ezek a branchek
  nincsenek teljesen benne foglaltatva a `HEAD`-ben.
