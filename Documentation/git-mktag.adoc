git-mktag(1)
============

NAME
----
git-mktag - Extra validációval hoz létre egy tag-objektumot


SYNOPSIS
--------
[verse]
'git mktag'

DESCRIPTION
-----------

Beolvassa egy tag tartalmát a standard bemeneten, és létrehoz egy
tag-objektumot. A kimenet az új tag <object> azonosítója.

Ez a parancs nagyjából egyenértékű a `-t tag -w --stdin`-nel
meghívott linkgit:git-hash-object[1]-gyel. Azaz mindkettő létrehozza
és kiírja a `my-tag`-ban található taget:

    git mktag <my-tag
    git hash-object -t tag -w --stdin <my-tag

A különbség az, hogy a mktag leáll, mielőtt kiírná a taget, ha az nem
megy át egy linkgit:git-fsck[1] ellenőrzésen.

A mktag által végzett "fsck" ellenőrzés szigorúbb, mint amit a
linkgit:git-fsck[1] alapértelmezés szerint futtatna, mivel minden
`fsck.<msg-id>` üzenet figyelmeztetésből hibává lesz előléptetve (így
pl. egy hiányzó "tagger" sor hiba).

Az objektumban lévő extra fejlécek is hibának számítanak a mktag
alatt, de a linkgit:git-fsck[1] figyelmen kívül hagyja őket. Ez az
extra ellenőrzés kikapcsolható a megfelelő `fsck.<msg-id>` változó
beállításával:

    git -c fsck.extraHeaderEntry=ignore mktag <my-tag-with-headers

OPTIONS
-------

--strict::
	A mktag alapértelmezés szerint bekapcsolja a
	linkgit:git-fsck[1] `--strict` módjának megfelelőjét. Használd
	a `--no-strict`-et a kikapcsolásához.

Tag-formátum
------------
Egy tag-aláírásfájlnak, amelyet ennek a parancsnak a standard
bemenetére adnak, egy nagyon egyszerű, rögzített formátuma van: négy
sor a következőkből:

  object <hash>
  type <typename>
  tag <tagname>
  tagger <tagger>

amelyet egy 'opcionális' szabad formátumú üzenet követ (néhány
régebbi Git által létrehozott tagnek nincs `tagger` sora). Az üzenet,
ha létezik, egy üres sorral van elválasztva a fejléctől. Az
üzenetrész tartalmazhat egy aláírást, amellyel maga a Git nem
törődik, de amely gpg-vel ellenőrizhető.

GIT
---
