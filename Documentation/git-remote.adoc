git-remote(1)
=============

NAME
----
git-remote - Követett repositoryk halmazának kezelése


SYNOPSIS
--------
[synopsis]
git remote [-v | --verbose]
git remote add [-t <branch>] [-m <master>] [-f] [--[no-]tags] [--mirror=(fetch|push)] <name> <URL>
git remote rename [--[no-]progress] <old> <new>
git remote remove <name>
git remote set-head <name> (-a | --auto | -d | --delete | <branch>)
git remote set-branches [--add] <name> <branch>...
git remote get-url [--push] [--all] <name>
git remote set-url [--push] <name> <newurl> [<oldurl>]
git remote set-url --add [--push] <name> <newurl>
git remote set-url --delete [--push] <name> <URL>
git remote [-v | --verbose] show [-n] <name>...
git remote prune [-n | --dry-run] <name>...
git remote [-v | --verbose] update [-p | --prune] [(<group> | <remote>)...]

DESCRIPTION
-----------

Azon repositoryk ("remote-ok") halmazának kezelése, amelyek branchét követed.


OPTIONS
-------

`-v`::
`--verbose`::
	Legyen kicsit bőbeszédűbb, és a név után mutassa a remote url-jét.
	Promisor remote-oknál azt is mutassa, mely szűrők (`blob:none` stb.)
	vannak beállítva.
	NOTE: Ezt a `remote` és az alparancs közé kell tenni.


COMMANDS
--------

Argumentumok nélkül a meglévő remote-ok listáját mutatja.  Több alparancs
áll rendelkezésre a remote-okon végzett műveletekhez.

`add`::

Hozzáad egy _<name>_ nevű remote-ot az _<URL>_ helyen lévő repositoryhoz.
A `git fetch <name>` parancs ezután használható a `<name>/<branch>`
remote-tracking branchek létrehozására és frissítésére.
+
A `-f` kapcsolóval a `git fetch <name>` közvetlenül a remote-információk
beállítása után lefut.
+
A `--tags` kapcsolóval a `git fetch <name>` minden taget importál a remote
repositoryból.
+
A `--no-tags` kapcsolóval a `git fetch <name>` nem importál tageket a remote
repositoryból.
+
Alapértelmezés szerint csak a fetchelt branchekhez tartozó tageket importálja
(lásd linkgit:git-fetch[1]).
+
A `-t <branch>` kapcsolóval az alapértelmezett glob refspec helyett, amely a
remote-ot a `refs/remotes/<name>/` névtér alatti összes branch követésére
állítja be, egy csak a _<branch>_ követésére szolgáló refspec jön létre.
Több `-t <branch>` is megadható több branch követéséhez anélkül, hogy az
összes branchet átvennéd.
+
A `-m <master>` kapcsolóval egy `refs/remotes/<name>/HEAD` symbolic-ref jön
létre, amely a remote _<master>_ branchére mutat. Lásd még a set-head
parancsot.
+
Amikor a `--mirror=fetch`-csel fetch-tükör jön létre, a refek nem a
`refs/remotes/` névtérben tárolódnak, hanem a remote-on lévő `refs/`-ben
minden közvetlenül a lokális repository `refs/`-ébe tükröződik. Ennek a
kapcsolónak csak bare repositoryban van értelme, mert egy fetch felülírná a
lokális commitokat.
+
Amikor a `--mirror=push`-sal push-tükör jön létre, a `git push` mindig úgy
viselkedik, mintha a `--mirror` át lenne adva.

`rename`::

Átnevezi az _<old>_ nevű remote-ot _<new>_-ra. A remote összes
remote-tracking branché és konfigurációs beállítása frissül.
+
Ha az _<old>_ és a _<new>_ megegyezik, és az _<old>_ egy fájl a
`$GIT_DIR/remotes` vagy a `$GIT_DIR/branches` alatt, a remote átalakul a
konfigurációsfájl-formátumra.

`remove`::
`rm`::

Eltávolítja az _<name>_ nevű remote-ot. A remote összes remote-tracking
branché és konfigurációs beállítása eltávolításra kerül.

`set-head`::

Beállítja vagy törli a megnevezett remote alapértelmezett branchét (azaz a
`refs/remotes/<name>/HEAD` symbolic-ref célját). Egy remote-nak nem
kötelező alapértelmezett branchcsel rendelkeznie, de lehetővé teszi, hogy a
remote nevét egy konkrét branch helyett adhasd meg. Például ha az `origin`
alapértelmezett branché `master`-re van állítva, akkor az `origin` megadható
bárhol, ahol normál esetben `origin/master`-t adnál meg.
+
A `-d` vagy `--delete` a `refs/remotes/<name>/HEAD` symbolic refet törli.
+
A `-a` vagy `--auto` esetén a remote-ot lekérdezi a `HEAD`-je
meghatározásához, majd a `refs/remotes/<name>/HEAD` symbolic-refet ugyanarra
a branchre állítja. Pl. ha a remote `HEAD` a `next`-re mutat, a
`git remote set-head origin -a` a `refs/remotes/origin/HEAD` symbolic-refet a
`refs/remotes/origin/next`-re állítja. Ez csak akkor működik, ha a
`refs/remotes/origin/next` már létezik; ha nem, előbb fetchelni kell.
+
A _<branch>_ használatával explicit módon állíthatod be a
`refs/remotes/<name>/HEAD` symbolic-refet. Pl. a
`git remote set-head origin master` a `refs/remotes/origin/HEAD`
symbolic-refet a `refs/remotes/origin/master`-re állítja. Ez csak akkor
működik, ha a `refs/remotes/origin/master` már létezik; ha nem, előbb
fetchelni kell.
+

`set-branches`::

Megváltoztatja a megnevezett remote által követett branchek listáját.
Ezzel az elérhető remote branchek egy részhalmaza követhető egy remote
kezdeti beállítása után.
+
A megnevezett branchek úgy értelmeződnek, mintha a `git remote add`
parancssorában a `-t` kapcsolóval lennének megadva.
+
A `--add` esetén a jelenleg követett branchek listájának cseréje helyett
ehhez a listához ad hozzá.

`get-url`::

Lekéri egy remote URL-jeit. Az `insteadOf` és a `pushInsteadOf`
beállításokat itt kifejti. Alapértelmezés szerint csak az első URL kerül
listázásra.
+
A `--push` esetén a fetch URL-ek helyett a push URL-eket kérdezi le.
+
A `--all` esetén a remote összes URL-je listázásra kerül.

`set-url`::

Megváltoztatja a remote URL-jeit. Az _<name>_ remote első olyan URL-jét,
amely illeszkedik az _<oldurl>_ regexre (az első URL-t, ha nincs _<oldurl>_
megadva), _<newurl>_-re állítja. Ha az _<oldurl>_ egyetlen URL-re sem
illeszkedik, hiba lép fel, és semmi sem változik.
+
A `--push` esetén a fetch URL-ek helyett a push URL-eket módosítja.
+
A `--add` esetén a meglévő URL-ek módosítása helyett új URL-t ad hozzá.
+
A `--delete` esetén a meglévő URL-ek módosítása helyett az _<name>_
remote-nál minden, az _<URL>_ regexre illeszkedő URL törlődik.  Az összes
nem-push URL törlésének megkísérlése hiba.
+
Vedd figyelembe, hogy a push URL-nek és a fetch URL-nek, még ha eltérően is
állíthatók be, ugyanarra a helyre kell hivatkoznia.  Amit a push URL-re
pusholtál, annak kell megjelennie, ha rögtön fetchelnél a fetch URL-ről.
Ha egy helyről (pl. az upstreamedről) fetchelsz, és egy másikra (pl. a
publikáló repositorydba) pusholsz, használj két külön remote-ot.


`show`::

Némi információt ad az _<name>_ remote-ról.
+
A `-n` kapcsolóval a remote headeket nem kérdezi le előbb a
`git ls-remote <name>`-mel; helyette gyorsítótárazott információt használ.

`prune`::

Törli az _<name>_-hez tartozó elavult referenciákat. Alapértelmezés szerint
az _<name>_ alatti elavult remote-tracking brancheket törli, de a globális
konfigurációtól és a remote konfigurációjától függően akár olyan lokális
tageket is kigyomlálhat, amelyeket nem pusholtak oda. Egyenértékű a
`git fetch --prune <name>`-mel, azzal a különbséggel, hogy nem fetchel új
referenciákat.
+
Arról, hogy különböző konfigurációktól függően mit gyomlál ki, lásd a
linkgit:git-fetch[1] PRUNING szakaszát.
+
A `--dry-run` kapcsolóval jelenti, mely branchek lennének kigyomlálva, de
ténylegesen nem gyomlálja ki őket.

`update`::

Frissítéseket fetchel a repositoryban lévő remote-okhoz vagy
remote-csoportokhoz, ahogyan azt a `remotes.<group>` meghatározza. Ha sem
csoport, sem remote nincs megadva a parancssorban, a `remotes.default`
konfigurációs paramétert használja; ha a `remotes.default` nincs definiálva,
minden olyan remote frissül, amelynél a `remote.<name>.skipDefaultUpdate`
konfigurációs paraméter nincs `true`-ra állítva.  (Lásd linkgit:git-config[1]).
+
A `--prune` kapcsolóval kigyomlálást futtat minden frissített remote-on.


DISCUSSION
----------

A remote konfigurálása a `remote.origin.url` és a `remote.origin.fetch`
konfigurációs változókkal érhető el.  (Lásd linkgit:git-config[1]).

EXIT STATUS
-----------

Siker esetén a kilépési állapot `0`.

Amikor az olyan alparancsok, mint az `add`, a `rename` és a `remove`, nem
találják a szóban forgó remote-ot, a kilépési állapot `2`. Amikor a remote
már létezik, a kilépési állapot `3`.

Bármely más hiba esetén a kilépési állapot bármely más, nem nulla érték
lehet.

EXAMPLES
--------

* Új remote hozzáadása, fetchelés, és egy branch checkoutolása belőle
+
------------
$ git remote
origin
$ git branch -r
  origin/HEAD -> origin/master
  origin/master
$ git remote add staging git://git.kernel.org/.../gregkh/staging.git
$ git remote
origin
staging
$ git fetch staging
...
From git://git.kernel.org/pub/scm/linux/kernel/git/gregkh/staging
 * [new branch]      master     -> staging/master
 * [new branch]      staging-linus -> staging/staging-linus
 * [new branch]      staging-next -> staging/staging-next
$ git branch -r
  origin/HEAD -> origin/master
  origin/master
  staging/master
  staging/staging-linus
  staging/staging-next
$ git switch -c staging staging/master
...
------------

* A `git clone` utánzása, de csak kiválasztott branchek követésével
+
------------
$ mkdir project.git
$ cd project.git
$ git init
$ git remote add -f -t master -m master origin git://example.com/git.git/
$ git merge origin
------------
