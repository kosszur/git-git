gitnamespaces(7)
================

NAME
----
gitnamespaces - Git névterek

SYNOPSIS
--------
[verse]
GIT_NAMESPACE=<namespace> 'git upload-pack'
GIT_NAMESPACE=<namespace> 'git receive-pack'


DESCRIPTION
-----------

A Git támogatja egyetlen repository referenciáinak több névtérre osztását,
amelyek mindegyikének saját branchei, tagei és HEAD-je van. A Git minden
névteret önálló repository-ként tud megjeleníteni, amelyből pullolni és
amelybe pusholni lehet, miközben az objektumtár közös marad, és az összes
referencia elérhető az olyan műveletek számára, mint a linkgit:git-gc[1].

Ha több repository-t egyetlen repository névtereként tárolsz, azzal
elkerülöd ugyanazon objektumok duplikált másolatainak tárolását, például
amikor ugyanannak a forrásnak több branchét tárolod. Az alternates
mechanizmus hasonló támogatást nyújt a duplikátumok elkerülésére, de az
alternates nem akadályozza meg a duplikációt a repository-khoz hozzáadott
új objektumok között folyamatos karbantartás nélkül, a névterek viszont
igen.

Egy névtér megadásához állítsd a `GIT_NAMESPACE` környezeti változót a
névtérre. Minden referencia-névtérhez a Git a megfelelő referenciákat egy
`refs/namespaces/` alatti könyvtárban tárolja. Például a
`GIT_NAMESPACE=foo` a `refs/namespaces/foo/` alatt tárolja a
referenciákat. Névtereket a linkgit:git[1] `--namespace` opcióján
keresztül is megadhatsz.

Vedd figyelembe, hogy a `/` jelet tartalmazó névterek névterek
hierarchiájává bomlanak ki; például a `GIT_NAMESPACE=foo/bar` a
`refs/namespaces/foo/refs/namespaces/bar/` alatt tárolja a referenciákat. Ez
hierarchikussá teszi a `GIT_NAMESPACE`-ben lévő útvonalakat, így a
`GIT_NAMESPACE=foo/bar` melletti klónozás ugyanazt az eredményt adja, mint a
`GIT_NAMESPACE=foo` melletti klónozás, majd az így kapott repóból való
klónozás `GIT_NAMESPACE=bar` mellett. Ezenkívül elkerüli a kétértelműséget
az olyan furcsa névtér-útvonalakkal, mint a `foo/refs/heads/`, amelyek
egyébként könyvtár/fájl ütközéseket okozhatnának a `refs` könyvtáron belül.

A linkgit:git-upload-pack[1] és a linkgit:git-receive-pack[1] a
`GIT_NAMESPACE` által megadott módon átírja a referenciák neveit. A
git-upload-pack és a git-receive-pack figyelmen kívül hagy minden, a
megadott névtéren kívüli referenciát.

A smart HTTP-szerver, a linkgit:git-http-backend[1], továbbadja a
GIT_NAMESPACE-t a backend programoknak; a linkgit:git-http-backend[1]
tartalmaz mintakonfigurációt ahhoz, hogy a repository-névtereket
repository-ként jelenítsd meg.

Egy egyszerű helyi teszthez a linkgit:git-remote-ext[1] használható:

----------
git clone ext::'git --namespace=foo %s /tmp/prefixed.git'
----------
