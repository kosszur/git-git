git-interpret-trailers(1)
=========================

NAME
----
git-interpret-trailers - Metaadat hozzáadása vagy értelmezése commit-üzenetekben

SYNOPSIS
--------
[synopsis]
git interpret-trailers [--in-place] [--trim-empty]
			[(--trailer (<key>|<key-alias>)[(=|:)<value>])...]
			[--parse] [<file>...]

DESCRIPTION
-----------
Trailer-metaadatot ad hozzá vagy értelmez egy commit-üzenet egyébként
szabad formátumú részének a végén, vagy bármilyen más szövegben.

Egy _trailer_ a legegyszerűbb formájában egy kulcs-érték pár, amelynek
az elválasztója egy kettőspont. A _kulcs_ ASCII alfanumerikus
karakterekből és kötőjelekből (`-`) áll. Egy _trailer-blokk_ egy vagy
több trailerből áll. A trailer-blokkot egy üres sornak kell megelőznie,
ahol egy _üres sor_ vagy egy teljesen üres, vagy egy csak whitespace-t
tartalmazó sor. Például a következő commit-üzenetben

------------------------------------------------
subject

Lorem ipsum dolor sit amet, consectetur adipiscing elit.

Signed-off-by: Alice <alice@example.com>
Signed-off-by: Bob <bob@example.com>
------------------------------------------------

az utolsó két, `Signed-off-by`-jal kezdődő sor trailer.

Ez a parancs a commit-üzeneteket vagy a _<file>_ argumentumokból olvassa
be, vagy a standard bemenetről, ha nincs _<file>_ megadva. Ha a
`--parse` meg van adva, a kimenet a bemenetről érkező, értelmezett
trailerekből áll, anélkül, hogy bármilyen parancssori kapcsolóval vagy
konfigurációs változóval befolyásolná őket.

Egyébként ez a parancs a `trailer.<key-alias>` konfigurációs változókat
(amelyek potenciálisan új trailereket adhatnak hozzá, valamint át is
helyezhetik őket), valamint bármely parancssori argumentumot, amely
felülbírálhatja a konfigurációs változókat (mint a `--trailer=...`,
amely szintén hozzáadhat új trailereket), alkalmazza minden bemeneti
fájlra. Az eredmény a standard kimenetre kerül.

Ez a parancs a linkgit:git-format-patch[1] kimenetén is működhet, amely
kidolgozottabb, mint egy sima commit-üzenet. Nevezetesen az ilyen
kimenet tartalmaz egy commit-üzenetet (mint fent), egy `---` elválasztó
sort és egy patch-részt. Ezeknél a bemeneteknél az elválasztó és a
patch-rész nem módosul e parancs által, és úgy, ahogy van, a kimenetre
kerül, hacsak a `--no-divider` nincs megadva.

Egyes konfigurációs változók vezérlik, hogyan alkalmazódnak a
`--trailer` argumentumok minden bemenetre, és hogyan változik a
bemenetben lévő bármely meglévő trailer. Lehetővé teszik azt is, hogy
automatikusan hozzáadódjanak bizonyos trailerek.

Vegyünk a `--trailer`-rel hozzáadott új trailereket. Alapból az új
trailer a trailer-blokk végén jelenik meg. Szintén alapból ez az új
trailer csak akkor adódik hozzá, ha az utolsó trailer különbözik tőle.
Egy trailer-blokk jön létre, amely csak azt a trailert tartalmazza, ha
még nem létezik trailer-blokk. Emlékezz, hogy egy trailer-blokkot egy
üres sornak kell megelőznie, így ebben az esetben egy üres sor kerül
beszúrásra az új trailer-blokk elé.

Így adódik hozzá az új trailer: egy `--trailer`-rel megadott
`<key>=<value>` vagy `<key>:<value>` argumentum a meglévő trailerek után
fűződik hozzá. A _<key>_ és a _<value>_ rész trimmelődik, hogy a kezdő
és a záró whitespace eltávolítódjon, és az így trimmelt _<key>_ és
_<value>_ így jelenik meg a kimenetben:

------------------------------------------------
key: value
------------------------------------------------

Ez azt jelenti, hogy a trimmelt _<key>_-t és _<value>_-t a
"`:`{nbsp}" (egy kettőspont, amelyet egy szóköz követ) választja el.

A meglévő trailerek úgy kerülnek kinyerésre a bemenetből, hogy a
trailer-blokkot keresi. Egy trailer-blokk egy vagy több sorból álló
csoport, amely (i) csupa trailer, vagy (ii) tartalmaz legalább egy Git
által generált vagy felhasználó által konfigurált trailert, és legalább
25%-ban trailerekből áll.
A trailer-blokk definíció szerint a commit-üzenet végén van. Az üzenet
pedig vagy (i) a bemenet végén van, vagy (ii) az utolsó nem
whitespace-sorok egy olyan sor előtt, amely `---`-mal kezdődik (amelyet
egy szóköz vagy a sor vége követ).

Kényelmi okból egy _<key-alias>_ konfigurálható, hogy a `--trailer`
használatát rövidebbé tegye begépelni a parancssorban. Ez a
`trailer.<key-alias>.key` konfigurációs változóval konfigurálható. A
_<key-alias>_-nak a teljes _<key>_ sztring előtagjának kell lennie, bár
a kis-nagybetűs érzékenység nem számít. Például ha ez van

------------------------------------------------
trailer.sign.key "Signed-off-by: "
------------------------------------------------

a konfigurációdban, akkor csak `--trailer="sign: foo"`-t kell megadnod a
parancssorban a `--trailer="Signed-off-by: foo"` helyett.

Trailerek olvasásakor nem lehet whitespace a _<key>_ előtt vagy azon
belül, de tetszőleges számú közönséges szóköz és tab karakter
megengedett a _<key>_ és az elválasztó között. Lehet whitespace a
_<value>_ előtt, azon belül vagy után. A _<value>_ több sorra
osztható, ahol minden következő sor legalább egy whitespace-szel
kezdődik, mint az RFC 822-beli "folding". Példa:

------------------------------------------------
key: This is a very long value, with spaces and
  newlines in it.
------------------------------------------------

OTHER RULES
-----------

Az előző szakaszban tárgyaltak azok a szabályok, amelyek a szokásos
használathoz relevánsak. A következő pontok a teljesség kedvéért
szerepelnek.

--
* Ez a parancs figyelmen kívül hagyja a komment-sorokat (lásd
  `core.commentString` a linkgit:git-config[1]-ben). Ez a
  `prepare-commit-msg` és `commit-msg` hookokkal való használatra való.

* Azok a trailer-jelölt sorok, amelyeknél `:` az elválasztó, amelyeknél
  nincs whitespace az értékrész előtt, és amelyek `//`-rel kezdődnek, nem
  ismerődnek fel trailerként. Ez azért van, hogy elkerülje az URL-ek
  véletlen trailerként való értelmezését (pl. a `https://`-rel kezdődő
  sorok).
--

OPTIONS
-------
`--in-place`::
`--no-in-place`::
	Helyben szerkeszti a fájlokat. Az alapértelmezés a `--no-in-place`.

`--trim-empty`::
`--no-trim-empty`::
	Ha bármely trailer _<value>_ része csak whitespace-t tartalmaz, az
	egész trailer eltávolítódik a kimenetből. Ez a meglévő trailerekre
	és az új trailerekre is vonatkozik.
+
Az alapértelmezés a `--no-trim-empty`.

`--trailer=<key>[(=|:)<value>]`::
`--no-trailer`::
	Megad egy (_<key>_, _<value>_) párt, amelyet trailerként kell
	alkalmazni a bemenetekre. Lásd e parancs leírását. Többször is
	megadható.
+
A `--no-trailer`-rel visszaállíthatod a listát.

`--where=<placement>`::
`--no-where`::
	Megadja, hova adódjon hozzá minden új trailer. A `--where`-rel
	megadott beállítás felülbírálja a `trailer.where`-t és bármely
	alkalmazható `trailer.<key-alias>.where` konfigurációs változót, és
	minden `--trailer` kapcsolóra vonatkozik a `--where` vagy a
	`--no-where` következő előfordulásáig. A lehetséges elhelyezések:
	`after`, `before`, `end` vagy `start`.
+
A `--no-where`-rel törölheted bármely korábbi `--where` használat
hatását, úgy, hogy a vonatkozó konfigurációs változók már nem
felülbíráltak.

`--if-exists=<action>`::
`--no-if-exists`::
	Megadja, milyen művelet hajtódjon végre, amikor már van legalább
	egy trailer ugyanazzal a _<key>_-vel a bemenetben. A `--if-exists`-szel
	megadott beállítás felülbírálja a `trailer.ifExists`-t és bármely
	alkalmazható `trailer.<key-alias>.ifExists` konfigurációs változót,
	és minden `--trailer` kapcsolóra vonatkozik a `--if-exists` vagy a
	`--no-if-exists` következő előfordulásáig. A lehetséges műveletek:
	`addIfDifferent`, `addIfDifferentNeighbor`, `add`, `replace` és
	`doNothing`.
+
A `--no-if-exists`-szel törölheted bármely korábbi `--if-exists`
használat hatását, úgy, hogy a vonatkozó konfigurációs változók már nem
felülbíráltak.

`--if-missing=<action>`::
`--no-if-missing`::
	Megadja, milyen művelet hajtódjon végre, amikor nincs másik trailer
	ugyanazzal a _<key>_-vel a bemenetben. A `--if-missing`-gel megadott
	beállítás felülbírálja a `trailer.ifMissing`-et és bármely
	alkalmazható `trailer.<key-alias>.ifMissing` konfigurációs változót,
	és minden `--trailer` kapcsolóra vonatkozik a `--if-missing` vagy a
	`--no-if-missing` következő előfordulásáig. A lehetséges műveletek:
	`doNothing` vagy `add`.
+
A `--no-if-missing`-gel törölheted bármely korábbi `--if-missing`
használat hatását, úgy, hogy a vonatkozó konfigurációs változók már nem
felülbíráltak.

`--only-trailers`::
`--no-only-trailers`::
	Csak a trailereket írja ki, a bemenet semmilyen más részét nem. Az
	alapértelmezés a `--no-only-trailers`.

`--only-input`::
`--no-only-input`::
	Csak azokat a trailereket írja ki, amelyek a bemenetben léteznek;
	nem ad hozzá egyet sem a parancssorból vagy a `trailer.<key-alias>`
	konfigurációs változók alkalmazásával. Az alapértelmezés a
	`--no-only-input`.

`--unfold`::
`--no-unfold`::
	Ha egy trailernek olyan értéke van, amely több sorra fut át (azaz
	"folded"), újraformázza az értéket egyetlen sorra. Az alapértelmezés
	a `--no-unfold`.

`--parse`::
	Kényelmi alias a `--only-trailers --only-input --unfold`-hoz. Ez
	megkönnyíti, hogy csak a bemenetről érkező trailereket lásd, anélkül,
	hogy bármilyen parancssori kapcsolóval vagy konfigurációs változóval
	befolyásolnád őket, egyben a `--unfold`-dal gépbaráttá téve a
	kimenetet.
+
Nincs kényelmi alias ennek az aliasnak a tagadására.

`--divider`::
`--no-divider`::
	A `---`-t a commit-üzenet végeként kezeli. Ez az alapértelmezés. A
	`--no-divider`-t akkor használd, amikor tudod, hogy a bemeneted
	csak magát a commit-üzenetet tartalmazza (nem egy e-mailt vagy a
	linkgit:git-format-patch[1] kimenetét).

EXAMPLES
--------

* Konfigurálj egy `sign` trailert `Signed-off-by` kulccsal, majd adj
  hozzá kettőt ezekből a trailerekből egy commit-üzenet fájlhoz:
+
------------
$ git config trailer.sign.key "Signed-off-by"
$ cat msg.txt
subject

body text
$ git interpret-trailers --trailer 'sign: Alice <alice@example.com>' --trailer 'sign: Bob <bob@example.com>' <msg.txt
subject

body text

Signed-off-by: Alice <alice@example.com>
Signed-off-by: Bob <bob@example.com>
------------

* Használd a `--in-place` kapcsolót egy commit-üzenet fájl helyben
  szerkesztéséhez:
+
------------
$ cat msg.txt
subject

body text

Signed-off-by: Bob <bob@example.com>
$ git interpret-trailers --trailer 'Acked-by: Alice <alice@example.com>' --in-place msg.txt
$ cat msg.txt
subject

body text

Signed-off-by: Bob <bob@example.com>
Acked-by: Alice <alice@example.com>
------------

* Nyerd ki az utolsó commitot patchként, és adj hozzá egy `Cc` és egy
  `Reviewed-by` trailert:
+
------------
$ git format-patch -1
0001-foo.patch
$ git interpret-trailers --trailer 'Cc: Alice <alice@example.com>' --trailer 'Reviewed-by: Bob <bob@example.com>' 0001-foo.patch >0001-bar.patch
------------

* Konfigurálj egy `sign` trailert egy paranccsal, amely automatikusan
  hozzáad egy "`Signed-off-by:`{nbsp}"-t a szerzőinformációval, csak akkor,
  ha még nincs "`Signed-off-by:`{nbsp}", és mutasd meg, hogyan működik:
+
------------
$ cat msg1.txt
subject

body text
$ git config trailer.sign.key "Signed-off-by: "
$ git config trailer.sign.ifmissing add
$ git config trailer.sign.ifexists doNothing
$ git config trailer.sign.cmd 'echo "$(git config user.name) <$(git config user.email)>"'
$ git interpret-trailers --trailer sign <msg1.txt
subject

body text

Signed-off-by: Bob <bob@example.com>
$ cat msg2.txt
subject

body text

Signed-off-by: Alice <alice@example.com>
$ git interpret-trailers --trailer sign <msg2.txt
subject

body text

Signed-off-by: Alice <alice@example.com>
------------

* Konfigurálj egy `fix` trailert olyan kulccsal, amely tartalmaz egy
  `#`-et, és nincs szóköz e karakter után, és mutasd meg, hogyan
  működik:
+
------------
$ git config trailer.separators ":#"
$ git config trailer.fix.key "Fix #"
$ echo "subject" | git interpret-trailers --trailer fix=42
subject

Fix #42
------------

* Konfigurálj egy `help` trailert egy cmd-vel, amely egy
  `glog-find-author` szkriptet használ, amely a megadott szerzői
  identitást keresi a git logból a git repository-ban, és mutasd meg,
  hogyan működik:
+
------------
$ cat ~/bin/glog-find-author
#!/bin/sh
test -n "$1" && git log --author="$1" --pretty="%an <%ae>" -1 || true
$ cat msg.txt
subject

body text
$ git config trailer.help.key "Helped-by: "
$ git config trailer.help.ifExists "addIfDifferentNeighbor"
$ git config trailer.help.cmd "~/bin/glog-find-author"
$ git interpret-trailers --trailer="help:Junio" --trailer="help:Couder" <msg.txt
subject

body text

Helped-by: Junio C Hamano <gitster@pobox.com>
Helped-by: Christian Couder <christian.couder@gmail.com>
------------

* Konfigurálj egy `ref` trailert egy cmd-vel, amely egy `glog-grep`
  szkriptet használ, hogy grep-elje az utolsó releváns commitot a git
  logból a git repository-ban, és mutasd meg, hogyan működik:
+
------------
$ cat ~/bin/glog-grep
#!/bin/sh
test -n "$1" && git log --grep "$1" --pretty=reference -1 || true
$ cat msg.txt
subject

body text
$ git config trailer.ref.key "Reference-to: "
$ git config trailer.ref.ifExists "replace"
$ git config trailer.ref.cmd "~/bin/glog-grep"
$ git interpret-trailers --trailer="ref:Add copyright notices." <msg.txt
subject

body text

Reference-to: 8bc9a0c769 (Add copyright notices., 2005-04-07)
------------

* Konfigurálj egy `see` trailert egy paranccsal, amely egy kapcsolódó
  commit subjectjét mutatja meg, és mutasd meg, hogyan működik:
+
------------
$ cat msg.txt
subject

body text

see: HEAD~2
$ cat ~/bin/glog-ref
#!/bin/sh
git log -1 --oneline --format="%h (%s)" --abbrev-commit --abbrev=14
$ git config trailer.see.key "See-also: "
$ git config trailer.see.ifExists "replace"
$ git config trailer.see.ifMissing "doNothing"
$ git config trailer.see.cmd "glog-ref"
$ git interpret-trailers --trailer=see <msg.txt
subject

body text

See-also: fe3187489d69c4 (subject of related commit)
------------

* Konfigurálj egy commit-sablont néhány üres értékű trailerrel (a
  sed-et használva a trailerek végén lévő záró szóközök megjelenítésére
  és megtartására), majd konfigurálj egy commit-msg hookot, amely a
  git-interpret-trailers(1)-et használja az üres értékű trailerek
  eltávolítására és egy `git-version` trailer hozzáadására:
+
------------
$ cat temp.txt
***subject***

***message***

Fixes: Z
Cc: Z
Reviewed-by: Z
Signed-off-by: Z
$ sed -e 's/ Z$/ /' temp.txt > commit_template.txt
$ git config commit.template commit_template.txt
$ cat .git/hooks/commit-msg
#!/bin/sh
git interpret-trailers --trim-empty --trailer "git-version: \$(git describe)" "\$1" > "\$1.new"
mv "\$1.new" "\$1"
$ chmod +x .git/hooks/commit-msg
------------

* Itt három különböző trailer-kulcsot próbálunk használni. De
  meghiúsul, mert kettő közülük nem ismerődik fel trailer-kulcsként.
+
----
$ cat msg.txt
subject

Skapad-på: some-branch
Hash-in-v6.11: 45c12d3269fe48f22834320c782ffe86c3560f2c
Reviewed-by: Alice <alice@example.com>
$ git interpret-trailers --only-trailers <msg.txt
$
----
+
Emlékezz, hogy egy trailer-kulcsnak csak ASCII alfanumerikus
karakterekből és kötőjelekből kell állnia, és ez nem áll fenn az első
két feltételezett trailer-kulcsra. És most egyik sem ismerődik fel
trailerként, mert a trailer-jelölt blokkban van legalább egy nem
trailer sor, még akkor is, ha a `Reviewed-by` egy érvényes
trailer-kulcs. Emlékezz, hogy egy trailer-blokknak vagy (i) csupa
trailernek kell lennie, vagy (ii) legalább egy Git által generált vagy
felhasználó által konfigurált trailerből kell állnia (és néhány egyéb
feltétel). És a (ii) nem teljesül, mivel nem konfiguráltunk semmilyen
trailer-kulcsot.
