gitformat-bundle(5)
===================

NAME
----
gitformat-bundle - A bundle fájlformátum


SYNOPSIS
--------
[verse]
*.bundle
*.bdl

DESCRIPTION
-----------

A Git bundle formátum egy olyan formátum, amely egyaránt ábrázol
referenciákat és Git-objektumokat. Egy bundle egy linkgit:git-show-ref[1]
kimenetéhez hasonló formátumú fejlécből áll, amelyet egy *.pack
formátumú pack követ.

A formátumot a linkgit:git-bundle[1] parancs hozza létre és olvassa, és
támogatja pl. a linkgit:git-fetch[1] és a linkgit:git-clone[1].


FORMAT
------

A Git bundle formátum meghatározásához ABNF-jelölést használunk. A
részletekért lásd a linkgit:gitprotocol-common[5]-öt.

Egy v2 bundle így néz ki:

----
bundle    = signature *prerequisite *reference LF pack
signature = "# v2 git bundle" LF

prerequisite = "-" obj-id SP comment LF
comment      = *CHAR
reference    = obj-id SP refname LF

pack         = ... ; packfile
----

Egy v3 bundle így néz ki:

----
bundle    = signature *capability *prerequisite *reference LF pack
signature = "# v3 git bundle" LF

capability   = "@" key ["=" value] LF
prerequisite = "-" obj-id SP comment LF
comment      = *CHAR
reference    = obj-id SP refname LF
key          = 1*(ALPHA / DIGIT / "-")
value        = *(%01-09 / %0b-FF)

pack         = ... ; packfile
----


SEMANTICS
---------

Egy Git bundle több részből áll.

* A "Capabilities" (képességek), amelyek csak a v3 formátumban vannak
	jelen, azt a funkcionalitást jelzik, amelyet a bundle a helyes
	beolvasáshoz megkövetel.

* A "Prerequisites" (előfeltételek) felsorolja azokat az objektumokat,
  amelyek NEM szerepelnek a bundle-ben, és amelyekkel a bundle olvasójának
  MUST már rendelkeznie ahhoz, hogy a bundle adatait használni tudja. A
  bundle-ben tárolt objektumok hivatkozhatnak előfeltétel-objektumokra és
  bármire, ami elérhető belőlük (pl. a bundle-ben lévő tree objektum
  hivatkozhat egy blobra, amely elérhető egy előfeltételből), és/vagy
  kifejezhetők előfeltétel-objektumokhoz viszonyított deltaként.

* A "References" (referenciák) rögzíti az előzménygráf csúcsait, más
  szóval azt, amit a bundle olvasója CAN belőle "git fetch"-elni.

* A "Pack" az a pack-adatfolyam, amelyet a "git fetch" küldene, ha egy
  olyan repository-ból fetchelsz, amelyben a fenti "References"-ben
  rögzített referenciák vannak, egy olyan repository-ba, amelynek
  referenciái a fenti "Prerequisites"-ben felsorolt objektumokra
  mutatnak.

A bundle formátumban egy előfeltétel obj-id-ját megjegyzés követheti.
Ez egy megjegyzés, és nincs konkrét jelentése. A bundle írója MAY ide
bármilyen karakterláncot tenni. A bundle olvasójának MUST figyelmen
kívül hagynia a megjegyzést.

[[_note_on_shallow_clones_and_git_bundles]]
Megjegyzés a shallow klónokról és a Git bundle-ökről
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Vedd figyelembe, hogy az előfeltételek nem jelölnek shallow-clone
határt. Az előfeltételek és a shallow-clone határok szemantikája
különbözik, és a Git bundle v2 formátum nem tud shallow clone
repository-t ábrázolni.

CAPABILITIES
------------

Mivel nincs lehetőség egyeztetésre, az ismeretlen capability-k hatására
a 'git bundle' megszakad.

* az `object-format` a használt hash algoritmust adja meg, és ugyanazokat
  az értékeket veheti fel, mint az `extensions.objectFormat` konfigurációs
  érték.

* a `filter` egy objektumszűrőt ad meg, ahogy a linkgit:git-rev-list[1]
  `--filter` opciójában. A kapott pack-fájlt `.promisor` pack-fájlként
  kell megjelölni, miután kicsomagolták.
